# open-backup 開発メモ (CLAUDE.md) / Development notes

**日本語**: 端末の大事なフォルダを、利用者自身の GitHub **非公開**リポジトリへ自動でバックアップするアプリです。Rust(コアと常駐エンジン)+ RPoem(`open-runo-crossui`)で作る画面+ Android アプリ。くわしくは [`README.md`](README.md)。**別のパソコンへ移るときや、作業を再開するときは [`PORTING.md`](PORTING.md)** を読んでください。
**English**: This app automatically backs up the important folders on a device to the user's own **private** GitHub repository. It is a Rust core and resident engine, a screen made with RPoem (`open-runo-crossui`), and an Android app. See [`README.md`](README.md) for details. **When you move to another computer or come back to the work, read [`PORTING.md`](PORTING.md).**

`aruaru-IME` とは**別のプロジェクト**です(混ぜないでください)。作業場所は `F:\open-backup`(`F:\runo` の中ではなく、となりのフォルダ)。
This is a **different project** from aruaru-IME (please do not mix them up). The working folder is `F:\open-backup` (next to `F:\runo`, not inside it).

## 方針 / Policy

**日本語**
- GitHub は必ず**非公開**。保存先が公開だったら、データを送らずに止まる。README に日英で警告を載せる。
- アカウントは作らない(利用者が自分で作る)。トークンは最小の権限(保存先 1 つだけの Contents 読み書き)で、利用者が自分で作る。値を画面・ログ・コミットに出さない。
- 個人のデータを外へ出さない(AI の分類は端末内の `aruaru-llm` だけ。送り先は `127.0.0.1` 固定)。
- `aruaru-llm` は端末に 1 つだけ(あれば相乗りする。tenant は `open-backup`)。
- 汎用にできる部分は RPoem へ(画面の生成は RPoem の `open-runo-crossui`)。Python は使わない(Rust)。
- 画面とインストーラーの試験ルール(複数の解像度・縦横・文字サイズ・下のボタン固定・インストールとアンインストール)は、`open-raid-z/CLAUDE.md` の「運用ルール」。
- 新しい REST は作らない(Connect と gRPC。例外は相手が形を決めるものだけ)。正本は `runo` の API 方針。
- 利用者の決めごと: 「ダウンロードするものは利用者が選んだものだけ」「GitHub は非公開だけ」「アカウントの作り方と最小権限トークンは利用者が自分で調べる(README に最低限の手順)」「Rust + RPoem で作る」「**実機への導入・公開・push は、許可を得てから**」「返事は日本語」。

**English**
- GitHub is always **private**. If the destination is public, stop without sending data. The README warns about this in Japanese and English.
- The app never creates accounts (the user does). The token has minimum rights (Contents read and write on one destination repository only) and is made by the user. Never print its value on screen, in logs or in commits.
- Personal data never leaves the device (AI sorting uses only the on-device `aruaru-llm`; the target is fixed to `127.0.0.1`).
- Only one `aruaru-llm` per device (share an existing one; tenant is `open-backup`).
- Put anything reusable into RPoem (the screen is generated by RPoem's `open-runo-crossui`). No Python (Rust only).
- UI and installer test rules (several resolutions, portrait and landscape, text sizes, bottom buttons fixed, install and uninstall) are in the "operating rules" of `open-raid-z/CLAUDE.md`.
- No new REST (Connect and gRPC; the only exceptions are shapes another party decides). The source of truth is the API policy in `runo`.
- The owner's rules: "download only what the user chose", "GitHub private only", "the user looks up how to make an account and a minimum-rights token (the README has the minimum steps)", "build with Rust + RPoem", "**ask before installing on a real device, publishing or pushing**" and "reply in Japanese".

## つまずきやすいところ / Pitfalls

**日本語**
- PowerShell 5.1 は、BOM の無い UTF-8 の日本語を読みまちがえます(日本語入りの `.ps1` は BOM 付きで)。日本語の編集は PowerShell ではなく、Edit/Write か Python(UTF-8)で。`Set-Content` は TOML をこわします。`Remove-Item` は、F: のパスと同じ命令にあると保護で止まります(命令を分ける)。
- GitHub は、リポジトリや内容を短い時間にたくさん作ると、二次レート制限(403)で止めます。テストは少しずつ。API の方法は 1 ファイルごとに約 0.7 秒あけます。
- **Android**: 画面(`ui/index.html`)は、Rust のエンジンに `include_str!` で入っています。画面やコアを変えたら、**必ず `android\build-android.ps1` でエンジンから作り直す**こと(Gradle の `assembleDebug` だけでは、アプリの中のエンジンが古いままです)。版を上げるときは `android/app/build.gradle` の `versionName` と `versionCode` も上げます。
- **adb**: 利用者の実機がつながっていることがあります(実機のシリアルは、つなぐたびに別かもしれません。`adb devices -l` で確かめる)。エミュレーターは `-s emulator-5554`。**実機への導入・更新は、許可を得てから。** `am start` は、設定画面がアプリの上に残っていると起動しません(`-f 0x10008000` を付ける)。
- **リリース**: `scripts\build-release.ps1` は、WSL での作成が失敗すると止まります(前は、古い Linux 版が黙って使われました)。**公開の前に、配布物に自分のユーザー名・パス・トークンが無いかを必ず確かめる**(`--remap-path-prefix` で消してあります)。
- 日本語を含む `perl -e` や、Bash のヒアドキュメントの `\` `\u` `\t` は、環境でこわれることがあります。編集は Edit/Write で。
- テスト用トークン(この開発機だけ): `F:\backup-token.txt`(`aon-co-jp-backup`)。本物のトークンは、OS の資格情報ストアに残さず、画面の `/login` にも入れません(環境変数 `OPEN_BACKUP_TOKEN` で渡す)。値は表示しません。
- 暗号化は、パスフレーズをなくすと戻せません。`crypt-init` は新しい salt を作るので、すでに暗号化したリポジトリへ、別の salt では書き込みません(断ります)。

**English**
- PowerShell 5.1 misreads Japanese text in UTF-8 files without a BOM (a `.ps1` with Japanese needs a BOM). Edit Japanese text with Edit/Write or Python (UTF-8), not PowerShell. `Set-Content` breaks TOML files. `Remove-Item` is blocked when it sits in the same command as an F: path (split the commands).
- GitHub stops you with a secondary rate limit (403) if you create many repositories or contents in a short time. Test a little at a time. The API way waits about 0.7 seconds per file.
- **Android**: the screen (`ui/index.html`) is built into the Rust engine with `include_str!`. When you change the screen or the core, **always rebuild from the engine with `android\build-android.ps1`** (Gradle's `assembleDebug` alone leaves an old engine inside the app). When you raise the version, also raise `versionName` and `versionCode` in `android/app/build.gradle`.
- **adb**: the owner's real device may be connected (its serial can be different each time; check with `adb devices -l`). Use `-s emulator-5554` for the emulator. **Ask before installing or updating on a real device.** `am start` does not start the app if a settings screen is still on top of it (add `-f 0x10008000`).
- **Releases**: `scripts\build-release.ps1` now stops if the WSL build fails (it used to reuse an old Linux binary silently). **Before publishing, always check that your own user name, paths and tokens are not in the files** (they are removed with `--remap-path-prefix`).
- `perl -e` with Japanese text and the `\`, `\u`, `\t` in Bash here-documents can break in this environment. Edit with Edit/Write.
- Test token (this development machine only): `F:\backup-token.txt` (`aon-co-jp-backup`). Never leave a real token in the OS credential store and never type it into the screen's `/login` (pass it with the environment variable `OPEN_BACKUP_TOKEN`). Never print its value.
- If you lose the passphrase, encrypted data cannot be restored. `crypt-init` makes a new salt, so the app refuses to write into an already-encrypted repository with a different salt.

## 暗号化・圧縮・並列・復元のメモ(2026-10-26) / Notes on encryption, compression, parallelism and restore

**日本語**
- **実装の場所**: `crates/open-backup-core/src/crypt.rs`(暗号化・復号・圧縮・目録・鍵)、`restore.rs`(復元・一覧)、`sync.rs`(`encrypt=true` なら、平文を作業コピーに置かず `crypt::sync_into` で処理)、CLI(`crypt-init` と `restore`)、エンジン(`/restore/list` `/restore/run` `/restore/status`。`127.0.0.1` だけ)、画面(`tools/gen-ui` の「復元」カード。作り直しは `cd tools/gen-ui && cargo run`)。
- **形式 v2**: `OBE2` | nonce(19 バイト) | { 長さ(u32 LE) | 暗号文 } のくり返し。かたまりの nonce = ファイル nonce | 番号(u32 BE) | 最後なら 1(STREAM と同じ組み立て。かたまりごとに並列で処理でき、途中切れは「最後」の印で見つけます)。かたまりの中身は [モード 0=そのまま / 1=zstd] + データ。AAD = `<ラベル>/<パス>`(ファイルの入れ替えを見つけます)。ファイル nonce = BLAKE3 の鍵つきハッシュ(パス + 中身)で、毎回同じになります(変わらなければ暗号文も同じ)。
- **試験**: `cargo test -p open-backup-core --release`(単体 + 通し: 暗号化 → 復元 → 同じ中身・名前が平文で出ない・変更なしなら差分 0・書き換えた 1 つだけ失敗・平文のリポジトリへの書き込みは断る)。速さの測定: `cargo test -p open-backup-core --release bench_throughput -- --ignored --nocapture`。実 GitHub を通す試験は `tests/e2e_github.rs`(手で動かす・`#[ignore]`)。
- **この作業で見つけて直したこと**: API の方法で、空のリポジトリの最初の保存に使う URL に `contents/` が無く、いつも 404 になっていました。

**English**
- **Where it lives**: `crates/open-backup-core/src/crypt.rs` (encrypt, decrypt, compress, catalog, key), `restore.rs` (restore and listing), `sync.rs` (with `encrypt=true` it never puts plain files in the work copy and uses `crypt::sync_into`), the CLI (`crypt-init` and `restore`), the engine (`/restore/list`, `/restore/run`, `/restore/status`; `127.0.0.1` only) and the screen (the "Restore" card in `tools/gen-ui`; regenerate with `cd tools/gen-ui && cargo run`).
- **Format v2**: `OBE2` | nonce (19 bytes) | repeated { length (u32 LE) | ciphertext }. Chunk nonce = file nonce | index (u32 BE) | 1 if last (the same build as STREAM, so chunks can be processed in parallel and truncation is caught by the "last" flag). A chunk holds [mode 0 = as is / 1 = zstd] + data. AAD = `<label>/<path>` (so swapped files are noticed). File nonce = keyed BLAKE3 hash of (path + content), so it is the same every time (unchanged input gives unchanged ciphertext).
- **Tests**: `cargo test -p open-backup-core --release` (unit tests plus a full round trip: encrypt, restore, identical content, no plain names, zero diff when nothing changed, only the one tampered file fails, writing into a plain repository is refused). Speed test: `cargo test -p open-backup-core --release bench_throughput -- --ignored --nocapture`. The real-GitHub test is `tests/e2e_github.rs` (run by hand, `#[ignore]`).
- **Bug found and fixed on the way**: in the API way, the URL used for the first save into an empty repository was missing `contents/`, so it always returned 404.
